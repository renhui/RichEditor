# AI 全栈模式下，人做什么、不做什么

> 对应：你要求「D0–D9 都由 AI 来写，原先需我开发的也由 AI 开发」

## 1. 原则

| 角色 | 职责 |
|---|---|
| **AI（或带 Agent 的编码助手）** | 生成/修改/补全 **全部** 实现：脚手架、Room/Repository、MVI 编辑器、图片、测试、Gradle、删除旧代码等 |
| **你（项目维护者）** | 不参与“为学习而手写 C 档”的硬性要求；改为 **验收、合并、真机验证、产品与风险决策** |

## 2. 你仍然需要做的事（不可替代）

这些事不是“写核心逻辑”，而是 **工程落地与质量闸门**：

1. **拉取与合并**  
   把 AI 产出的 diff 合进你的分支；解决与本地工具有关的冲突（极少见）。

2. **本地/CI 验证**  
   `./gradlew :app:assembleDebug`（或模块名以实际为准）、Lint、单测；在真机/模拟器上点通主路径。

3. **环境差异**  
   JDK 版本、Android Studio 版本、SDK 路径若与 AI 假设不一致，由你调整 `local.properties` 等（AI 可给建议，你执行）。

4. **密钥与第三方**  
   若未来接入云同步、统计等，**不把密钥交给 AI 明文**；只给占位符，由你本地注入。

5. **产品拍板**  
   主题色、功能裁剪（例如是否保留手写板）、发布渠道 —— 由你决定，AI 按指令改。

6. **法律与隐私**  
   依赖库许可证、用户协议、权限声明的最终责任在你。

## 3. 你不必做的事（在本模式下）

- 不必为完成度而 **强制手敲** `EditorViewModel`、撤销栈、Flow 组合等（原 `DEV_PLAYBOOK` 的 🟥 C 档）。
- 不必 **拒绝** AI 直接提交的 MVI/性能优化代码；改为 **审查 + 测试** 通过即可。

## 4. 与 `DEV_PLAYBOOK.md` 的差异

| 项目 | `DEV_PLAYBOOK.md` | `doc/dev`（本模式） |
|---|---|---|
| C 档（核心逻辑） | 必须你亲手写，AI 出的不算完成 | **AI 写**，你 Review + 测试 |
| 学习笔记 | 每阶段强制 | **可选**；可改为「阶段小结」由 AI 代写，你审阅 |
| 代码所有权 | 强调个人肌肉记忆 | 强调 **可运行、可维护、可回滚** |

## 5. 若你仍想“边用 AI 边学”

- 在 **合并前** 自己读一遍 AI 提交的 `EditorViewModel` / `NoteRepository`，用 `DEV_PLAYBOOK` 的「自学产出」问题自测。
- 不要求每行都自己敲，**读懂**即可与招聘/面试要求对齐。
